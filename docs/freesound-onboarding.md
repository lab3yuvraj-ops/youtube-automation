# Agent-assisted Freesound setup

Trigger: the user asks to retrieve their Freesound client ID, client secret, or refresh token using their connected browser, or to import them from a specific Google Sheet.

1. Read the available browser/computer-use skill and use its supported tools with the user's connected Chrome session. Do not scrape browser profiles, cookies, password stores or unrelated accounts. If the browser connection is unavailable, explain that it must be connected before this step can run.
2. If a Google Sheet is explicitly specified, open only that sheet and retrieve the named Freesound fields. Ask for the sheet link if none is supplied; do not guess which sheet or search unrelated documents. Sheets can hold existing credentials; they cannot issue a new OAuth token. Do not write credentials back to a Sheet. Otherwise use the authenticated Freesound account at https://freesound.org/apiv2/apply/ and its linked API credential management page.
3. Reuse this user's existing app credential when appropriate. If no app exists, register one for YouTube Automation using truthful details. Obtain missing required app details from the user. Let the user handle login, CAPTCHA, and any consent that the browser tool requires them to perform. Never claim completion while waiting for these steps.
4. Save client ID and client secret directly to `scripting/.env`, preserving every unrelated key and comment. Never print secret values or put them in command arguments. Use local file tools, with safe literal serialization. Use the keys FREESOUND_CLIENT_ID and FREESOUND_CLIENT_SECRET. For an existing refresh token, also save FREESOUND_REFRESH_TOKEN.
5. If no refresh token exists, use the official OAuth authorization flow described at https://freesound.org/docs/api/authentication.html. Open https://freesound.org/apiv2/oauth2/authorize/?client_id=CLIENT_ID&response_type=code with the actual client ID using the connected browser. Complete the user's authorized permission flow. Save the returned code temporarily as FREESOUND_AUTHORIZATION_CODE in the local .env. Do not put the code in shell arguments or chat. Use the registered app's redirect behavior; do not invent a redirect URL.
6. From production, run `npm run freesound -- --auth-only`. This exchanges the saved authorization code (or validates an existing refresh token), saves the newly issued refresh token, and removes the temporary code. It does not download music. Only a successful response confirms configuration. If the code expires, repeat authorization rather than guessing tokens.
7. Report only that credentials were saved and validated, or the actual blocker. Never include the values. Credentials belong to each student; never copy the repository owner's credentials.

Freesound rotates refresh tokens, so every successful refresh must save the replacement locally. Google Sheet import still needs token validation. Browser credential retrieval requires a connected browser-capable agent; ordinary Git clone/npm scripts cannot control an extension on their own.
