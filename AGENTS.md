# YouTube Automation operating rules

When the user supplies a video title, start a new local project from that title using `start-video.ps1`. The scripting stage must retain the literal templates in `scripting/prompts/`, produce a one-minute Hindi folk-horror story with exactly 12 scenes, and preserve the reference style: flat, semi-realistic 2D Indian animation with natural adult human proportions. Use `OPENAI_API_KEY` when available; otherwise use `GROQ_API_KEY`. Never store either key in the repository.

Run Google Flow only through the authenticated persistent local Chrome profile. Create characters, backgrounds, then scenes; download every completed scene. Never require or assume six-second clips: Flow determines the natural duration required for each action and spoken line.

For every non-character-speaking scene, generate the matching Hindi narrator audio in Google AI Studio. Try Run twice. If no audio is produced, pause and say exactly: **“Hey, when I open Google AI Studio, just click on the Run button so I can proceed.”** Never continue a silent scene if narration is expected.

Edit clips in scene order. Preserve full character dialogue, trim only unused narrator padding, use brief fade transitions, retain Flow character audio on character-speaking scenes, and add a premium fade/pop title only over scene 1. On non-character scenes, use the Google AI Studio Hindi narrator file, keep any useful scene ambience/SFX quietly beneath it, and never leave a silent gap. Normalize the continuous horror music bed to -20.9 LUFS. Process narrator tracks with the tested compressor/limiter chain for approximately -14 LUFS; never target 0 LUFS because it is a full-scale clipping level, not a safe spoken-audio loudness target. Use the permanent lower-right brand placement: at 1280x720, 76px high, 72px inset from the right, 75px inset from the bottom. Do not store or commit API keys, browser profiles, downloaded media, project outputs, private intro/logo files, or `.env` files.

After the final title render, record an `awaiting_approval` review state and ask one question: **“Is this video good enough to upload to YouTube?”** Show the final video, destination account and visibility. Approval authorizes automatic upload through Zernio without a second confirmation. Rejection does not upload. Collect the API key and connected YouTube account ID through local setup, never in chat. Use `review approve` or `review prompt`. Never bypass review or resubmit a project with a submission marker.

When a user says **“onboarding”**, respond exactly: **“Welcome to YouTube Automation! Please provide your channel logo (transparent PNG) and intro video (MP4, at least 5 seconds long, with audio).”** If the assets are already configured, acknowledge them instead of asking again. The onboarding response must ask only for these two assets. Read all other configuration from `scripting/.env`; do not ask for API keys in the onboarding response or in chat. Store supplied assets locally at the configured paths. Git itself does not execute this message; the agent delivers it when the user says “onboarding,” and `npm run setup` shows it when setup is incomplete.

When the user explicitly asks to get Freesound credentials through their connected Chrome browser or a specified Google Sheet, follow `docs/freesound-onboarding.md`. This is an agent-assisted browser workflow, not an unattended scraper. Complete authorized credential retrieval and local configuration without asking for redundant permission. Never expose credentials in replies, logs, screenshots shared with others, or Git.
